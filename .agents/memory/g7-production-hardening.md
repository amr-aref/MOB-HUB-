## Critical: products + stores were full-table-scan

`GET /products` and `GET /stores` fetched ALL rows then filtered in JS.
Fixed by pushing all filters to SQL WHERE using Drizzle `and()`, `eq()`, `ilike()`, `inArray()`, `ne()`, `or()`.

## Missing indexes (were added in G.7)

All tables below had zero non-PK indexes before G.7:
- `products`: storeId, category, isNew, isBestSeller, isFeatured
- `stores`: governorate, isVerified, rating
- `conversations`: buyerId, storeId, lastMessageAt, (buyerId+storeId+productId) composite
- `chat_messages`: (conversationId, createdAt) composite
- `reviews`: (storeId, status), (storeId, userId), productId

## recalculateStoreRating was O(N)

Fetched all active review rows just to compute avg + count. Fixed to single SQL `avg() + count()` aggregation.

## Notification read + delete: was 2 queries, now 1

`markNotificationRead` already returns the updated row via `.returning()` — if undefined, it's a 404.
`deleteNotification` changed to return `boolean` via `.returning({ id })` length check.

## TanStack Query v5 + Orval queryKey type issue

**Problem**: Orval v8.20 generates `options.query?: UseQueryOptions<...>` but TQ v5 `UseQueryOptions` requires `queryKey`. Callers passing `{ query: { enabled: true } }` get a TS2741 error.

**Fix**: Add a type alias in the generated `api.ts`:
```typescript
type QueryOpts<TData, TError = unknown, TSelected = TData> = Omit<UseQueryOptions<TData, TError, TSelected>, 'queryKey'> & { queryKey?: QueryKey };
```
Then replace all `query?:UseQueryOptions<` → `query?:QueryOpts<` in the generated file (44 occurrences).
The internal Orval code reads `queryOptions?.queryKey ?? autoGeneratedKey` which works fine with optional queryKey.

**Why**: This is a generated file — if Orval is re-run, this fix must be re-applied.

## createReservation mobile call bug

`product/[id].tsx` was calling `createReservation({ data: { productId, buyerId } })` but the mutation signature is `{ id: string; data: CreateReservationBody }`. Fixed to `createReservation({ id: product.id, data: { buyerId } })`.

## Error handler: strip query params from logged URL

Query params in error logs can contain `buyerId`, `storeId` — sensitive device identifiers.
Fix: `req.url.split("?")[0]` before logging.

## Messages list: add LIMIT 200

`GET /conversations/:id/messages` had no limit. Added `.limit(200)` to prevent unbounded payloads for long conversations.

## Stores reviews: add ORDER BY + LIMIT 100

`GET /stores/:id/reviews` had no ordering or limit. Added `.orderBy(desc(createdAt)).limit(100)`.

## Mobile memoization

- `ProductCard`: wrap in `React.memo` + `useCallback` for all 4 event handlers
- Home screen `reservationStatusMap`: wrap `new Map(...)` in `useMemo([myReservations])`
- Messages screen `uniqueStoreIds`: wrap `Array.from(new Set(...))` in `useMemo([conversations])`
- Messages screen `handleOpen`: `useCallback([router])`
