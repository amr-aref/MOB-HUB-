---

# SPRINT: Production Hardening Phase 2 — Enterprise Reliability & Codebase Modernization

You are acting as a **Principal Software Architect, Senior Backend Engineer, Senior React Native Engineer, DevOps Lead, Database Architect, Security Engineer, Performance Engineer, and Code Quality Reviewer** working together on the **MOB HUB** production codebase.

The previous hardening phase has already completed several improvements including:

* Notification IDOR protection
* Response compression
* PostgreSQL connection pool tuning
* Trust proxy configuration
* Dependency cleanup
* ESLint warning reduction
* API and Mobile app successfully running

Your task is **NOT** to redesign the project.

Your task is to evolve the existing architecture into a **production-grade, enterprise-quality codebase** while preserving existing behavior.

---

# PRIMARY OBJECTIVE

Increase the engineering quality of the repository while maintaining complete feature compatibility.

Do NOT introduce regressions.

Do NOT break API contracts.

Do NOT remove existing business features.

Do NOT redesign UI.

Focus entirely on reliability, maintainability, consistency, security, stability, and production readiness.

---

# EXECUTION RULES

Before modifying anything:

Perform a full repository audit.

For every proposed change:

* verify impact
* identify dependencies
* avoid breaking public interfaces
* preserve OpenAPI compatibility
* preserve database compatibility unless migration is required

Never modify code blindly.

Always understand the execution flow before editing.

---

# TASK 1 — Transaction Atomicity

Find every multi-step database operation.

Examples include:

* create review
* update review
* delete review
* create conversation
* create message
* reservation workflow
* order workflow

Wrap every multi-query operation inside proper Drizzle/PostgreSQL transactions.

Guarantee ACID behavior.

Guarantee rollback on failure.

Prevent partial writes.

Remove every possibility of inconsistent data.

---

# TASK 2 — Race Condition Elimination

Audit every place where aggregate values are recalculated.

Especially:

* store ratings
* review count
* message count
* reservation state
* unread counters

Prevent race conditions.

Ensure concurrent requests always produce correct values.

Use transactional locking or equivalent safe database mechanisms.

---

# TASK 3 — Validation Hardening

Audit every route.

Ensure every endpoint validates:

* params
* query
* request body
* enums
* IDs
* pagination
* limits
* sort fields
* filters

No endpoint should trust client input.

Standardize all validation.

Return consistent error responses.

---

# TASK 4 — Shared Utilities

Eliminate duplicated logic.

Create reusable infrastructure for:

* pagination
* DTO mapping
* filters
* query builders
* response formatting
* API errors
* validation helpers

Replace duplicated implementations with shared utilities.

Improve readability.

Reduce maintenance cost.

---

# TASK 5 — Error Handling

Audit every async route.

No unhandled promise.

No duplicated try/catch blocks.

Improve centralized error middleware.

Classify errors into:

* Validation
* Authentication
* Authorization
* Business
* Database
* Internal

Return standardized responses.
