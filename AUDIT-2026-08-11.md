# MOB HUB — Repository Audit

Date: 2026-08-11

## Product model
MOB HUB is a phone marketplace and reservation system only. There is no online purchase, checkout, payment gateway, or in-app payment. Customers reserve phones and pay inside the physical store.

## P0 completed
- Production CORS allow-list enforcement.
- Strong JWT secret requirements and JWT claim validation.
- Active database-session validation on protected requests.
- Current DB role/store state used for authorization.
- Public registration cannot self-assign privileged roles or arbitrary stores.
- Dashboard authentication, RBAC and merchant store-ownership enforcement.
- Removal of unsafe demo-store authorization fallback.
- Product input validation and secure ID generation.
- Reservation API authentication and ownership derived from the authenticated session.

## P1 completed
- Shared marketplace search submits to a real search-results route.
- Search results use the products API and open real product details.
- Persisted mobile authentication validates `/auth/me` and uses refresh-token rotation.
- Public mobile registration no longer accepts privileged role/store fields.
- Product Details uses reservation semantics rather than purchase semantics.
- Reservation creation, listing, details, cancellation and lifecycle API are implemented.
- My Reservations and Reservation Detail screens exist and consume reservation API data.
- Merchant reservation actions are protected by authenticated role/store ownership.
- Existing mobile clients may still send a device UUID as a legacy buyerId value; the API does not trust it for authorization and derives buyer identity from the authenticated session.
- Compare, favorites, stores, profile, product, products/search and reservations routes exist.
- No cart, checkout or payment functionality is part of the product flow.
